# NOMAD AI Factory — Stitch AI 디자인 기획서
## UI 설계 실무 가이드 (Stitch → Claude Code 완전 연결)

> **버전:** v1.0.0 | **작성일:** 2026-06-16  
> **목적:** 지금까지 작성한 모든 기획안을 통합해 Stitch에서 UI를 뽑아내는 실무 순서와 프롬프트 전체 정리  
> **Stitch 접속:** stitch.withgoogle.com

---

## 0. Stitch 작업 전 핵심 이해

```
Stitch에 넣는 파일:   DESIGN_FOR_STITCH.md (1개만)
Stitch 결과물:        HTML/CSS 코드 + Figma Export
Claude Code에 넣는 파일: PRD.md + DESIGN.md + CLAUDE.md (3개)
참조 문서:            @MARKET_IMAGE_SPEC.md @MARKET_REGISTER_FORM.md
                      @DETAIL_PAGE_SYSTEM.md @NOMAD_AI_FACTORY_MASTER_SPEC.md

Stitch 작업 순서:
  1. 프로젝트 생성 → DESIGN_FOR_STITCH.md 업로드
  2. 화면 순서대로 프롬프트 입력 (이 문서의 화면별 프롬프트 복사)
  3. Direct Edit으로 세부 수정
  4. 완성 화면 → Figma Export or HTML 코드 복사
  5. Claude Code에 전달 → 구현
```

## 1. Stitch 프로젝트 초기 설정

### 1.1 DESIGN.md 업로드 방법
```
stitch.withgoogle.com → 새 프로젝트 생성
→ 우측 상단 ⚙️ 설정 → DESIGN.md 탭 → 파일 업로드
→ DESIGN_FOR_STITCH.md 업로드
→ "이제 이 디자인 시스템을 기반으로 모든 화면을 생성하겠습니다." 확인
```

### 1.2 AI 모드 선택 기준
| Stitch 모드 | 언제 사용 |
|------------|---------|
| **Gemini 3 Flash** | 초안 빠르게 / 여러 안 비교할 때 |
| **Gemini 3 Pro** | 완성도 높은 최종 화면 / 복잡한 컴포넌트 |
| **Vibe Design** | 감성 방향 탐색 / 초기 컨셉 잡을 때 |
| **Voice Canvas** | 세부 수정 지시 / 직접 편집 불편할 때 |

### 1.3 Zoom-Out-Zoom-In 프롬프트 공식 (필수)
```
[A. 제품 컨텍스트]   → 어떤 서비스인가 (1~2문장)
[B. 이 화면의 목적]  → 유저가 이 화면에서 무엇을 해야 하는가
[C. 레이아웃 계층]   → 화면 구조 위→아래 or 좌→우 순서
[D. 핵심 컴포넌트]   → 반드시 포함해야 하는 요소들
[E. 디자인 톤]       → DESIGN.md 기반 특이사항
```


## 8. 디자인 방향 — 화면 유형별 톤 가이드

Stitch 생성 전 각 화면의 "느낌"을 잡아주는 디자인 지침.

### 8.1 운영 화면 (대시보드, 상품 목록, 판매 관리)
```
톤: 전문적, 정보 밀도 높음, 속도감
특징:
  - 숫자가 주인공 → Bebas Neue + JetBrains Mono 적극 활용
  - 흰색 카드 + 연회색 배경의 명확한 대비
  - 색상은 상태 표현에만 (초록=완료, 파랑=진행, 빨강=오류)
  - 불필요한 장식 요소 완전 제거
  - 행 높이 충분히 (56px) → 빠른 스캔 가능
Stitch 지시어: "clean, data-rich, professional dashboard"
```

### 8.2 생성 워크플로우 (상세페이지 생성, 쇼츠, 카드뉴스)
```
톤: 명확한 단계, 설정 집중, 피드백 즉각적
특징:
  - 단계별 진행이 명확하게 보여야 함 (Step Indicator, 탭 구조)
  - 설정 항목은 체크박스/라디오/토글 일관되게 사용
  - 진행 중 상태: Progress Bar + 현재 단계 텍스트 실시간 업데이트 표현
  - 완료 피드백: 초록 체크 + 간단한 성공 메시지
Stitch 지시어: "step-by-step wizard, progress feedback, clear options"
```

### 8.3 배포 화면 (마켓 배포, SNS 업로드)
```
톤: 신뢰감, 정확성, 완성도 확인
특징:
  - 마켓별 완성도 %가 시각적으로 명확해야 함
  - 경고(⚠️)와 오류(❌)가 즉각 눈에 띄어야 함
  - 배포 실행 버튼은 가장 크고 강조된 형태
  - 성공 후: 마켓 직접 확인 링크 제공
Stitch 지시어: "confirmation-focused, warning-aware, action-oriented"
```

### 8.4 자동화 화면 (React Flow, n8n, Make)
```
톤: 개발자 친화적, 기술적, 캔버스 중심
특징:
  - 배경: 격자 패턴(grid) 반드시 표현
  - 노드 카드: 깔끔한 흰색, 상단 색상 바로 카테고리 구분
  - 연결선: 명확한 화살표
  - 사이드 패널: 노드 목록 카테고리별 정리
Stitch 지시어: "technical canvas, node-based, developer-friendly"
```

### 8.5 설정/계정 화면
```
톤: 정리됨, 명확한 상태 표시
특징:
  - 좌측 세로 탭으로 섹션 구분
  - 연결됨/미연결 상태 뱃지 명확
  - API 키: 항상 mono 폰트 + 마스킹 처리
  - 위험한 설정(연결 해제, 구독 취소): danger 색상 버튼
Stitch 지시어: "settings page, clear status, organized sections"
```

### 8.6 랜딩 페이지
```
톤: 마케팅, 임팩트, 신뢰감
특징:
  - 다크 히어로 섹션 (#0F1117 → #1a2035)
  - Bebas Neue 대형 헤드라인
  - 민트(#00C9A7) 포인트 컬러 강조
  - 실제 UI 목업 스크린샷 활용
  - CTA 버튼 크게, 여백 충분히
Stitch 지시어: "marketing landing, dark hero, SaaS product showcase"
```

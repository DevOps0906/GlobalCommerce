인자: `tokens` | 화면 ID(`GC-S-01` ~ `GC-S-18`) | `shell` | 비우면 `tokens` + `shell`. 예: `/sync-design tokens`, `/sync-design GC-S-06`

기준 자료(읽기만, 수정하지 않는다):
- 토큰 표: `docs/design/dashboard/README.md` "디자인 토큰" 절, `products/00_DECISIONS.md` GC-D-19(토큰 정본 · 포인트 색) · GC-D-20(반응형 3구간 · 글자 크기 · 셸 폭)
- 화면: `docs/design/dashboard/<파일>.dc.html` — 화면 ID ↔ 파일 ↔ 경로는 `00_DECISIONS.md` 5.2 표. 공용 셸은 `Sidebar.dc.html`(메뉴 순서 정본) · `TopBar.dc.html`
- 캔버스 파일은 캔버스 런타임 전제라 단독으로 열면 깨진다. 마크업 · 문구 · 수치 참고용으로만 읽는다. 숫자 · 상품은 예시 데이터이고, 플랜 한도 · 가격은 `00_DECISIONS.md` GC-D-04 · 7절이 이긴다.

1. **tokens** — 토큰 표의 역할별 값(바탕 · 표면 · 구분선 · 본문 · 포인트 채움/글자 · 틴트 · 상태 4색 · 서체 3종)과 GC-D-20 글자 크기 · 셸 폭을
   `apps/web/styles/tokens.css`(Tailwind CSS v4 `@theme`)와 비교한다. 파일이 없으면 "코드 착수 전"으로 보고하고 기준 값 표만 만든다.
   AA 규칙도 본다: 포인트 버튼 · 글자는 #007A64 계열 토큰, #00C9A7 은 채움 전용. 다크 토큰은 두 번째 벌로 정의돼 있는지(O-08).
2. **shell** — 사이드바 메뉴 순서 · 표기 · 릴리스별 숨김(R2 · R3 메뉴 미렌더, 플랜 잠금은 배지), 상단 바 구성, 태블릿 아이콘 레일 64px · 모바일 하단 탭 5개를
   `apps/web`의 공용 셸 컴포넌트와 비교한다.
3. **화면 ID** — 해당 `.dc.html`의 영역 구성 · 문구 · 상태 표현(빈 · 로딩 · 오류 · 진행)과 `apps/web/app/` 아래 해당 경로 구현을 비교한다.
   반응형 디자인 파일이 있는 화면(대시보드 · 업로드)은 태블릿 · 모바일 파일도 함께 본다.
4. 결과를 "항목 / 디자인 값(파일:위치) / 코드 값(file:line) / 차이" 표로 만든다. 디자인이 `00_DECISIONS.md`와 다른 곳(7절 목록 등)은 "디자인 수정 대상"으로 따로 적는다.
5. 코드는 고치지 않는다. 토큰 차이를 `tokens.css`에 반영할지, 화면 차이를 `tasks/README.md` "발견한 문제" 표에 제안으로 적을지 사용자에게 묻는다.
   반영을 승인받으면 토큰 값 반영은 nextjs-expert 에게(토큰 파일만, 컴포넌트 수정 없음), 값 추출이 많으면 사원(sub-agent-2)에게 먼저 맡긴다.
